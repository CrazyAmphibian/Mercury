predefined global variables

besides the variables provided by libraries (which will be covered next chapter), states come with 2 predefined variables that can be accessed no matter what.
the first one is the global environment table, _G
the second one is the local environment table, _ENV
when in the topmost state (the master state), _ENV and _G are the same object.

a=10
print(_ENV.a) //prints 10
_ENV.a=nil
print(a) //prints nil

because environments use ordinary tables, it means you can modify them in whichever way you want, as they are still first class, and the only exceptions to them is that environmental tables are protected from being freed.
though, they cannot be deleted, only their contents

_G=nil
print("still works") //while _G was removed, the table still is held in the state, and so enviromental access still works
_G="hello" //valid, as the value associated with "_G" is changed, since _G is usually just a table being stored like any other

do note that, while these are tables are tables like any other, they are treated differently, and should be considered volatile storage, and no guarantee is made that the contents of the table won't be changed by the runtime. environmental tables (especilly _ENV) should not be used for persistent storage.

mercury runtime

when running mercury from it's executable, a new global is added, _ARGS. this is an array of the command line arguments which led to the executable being ran. args passed to the language start at 0, though negative index args exist and represent the executable's args, not the language's.

consider the following startup command

mercury -n test_value=22

and in mercury:

print(_ARGS[0]) // test_value=22
print(_ARGS[-1]) // -n
print(_ARGS[-2]) // mercury

command line arguments

when running the standalone executable, mercury (the executable) has some args that changes what it does.
mercury uses the following syntax for starting the executable: mercury [options] <file> [runtime args]

executable arg effect
-?
-h
--help
/?		 shows a help message displaying all args, then exits
-v
--version
/v		 displays the version, then exits
-i
--interactive
/i		 enables interactive mode. implied if no file is given
-n
--no-file
/n		 Starts with no input file, treating all following args as for the runtime.
