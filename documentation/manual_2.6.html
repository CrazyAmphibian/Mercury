overview

Mercury is easily embeded into another codebase to add an easy and dynamic language for extensions or faster development.
this document will cover how to set up the basic mercury runtime environment.
the details of setting up an API between mercury and your project will be up for you to decide, and the previous chapters go over some of the technicalities of the language.

the basics

mercury uses state objects to run code. you will need to make one. you can decide yourself if you want a shared global state or not, either way the code will be similar.
the following is a basic setup to run mercury code stored in a char*, code_to_execute, then remove the mercury runtime state once finished.

#include "mercury.hpp"
#include <string.h>
#include <malloc.h>

mercury_state* M=mercury_newstate(); //creates the state
mercury_populate_table_with_libs(M->enviroment); //adds mercury libraries into the environment

mercury_string intermediate; //function takes a mercury_string, not a char*
intermediate.ptr = code_to_execute;
intermediate.size = strlen(code_to_execute);
mercury_variable compile_output; //function outputs into a variable, since there's multiple return types.
mercury_compile_mstring(&intermediate,&compile_output); //compile a string as code.

if(compile_output.type!=M_TYPE_FUNCTION){
  //handle comipler error here
}else{
  M->bytecode = *((mercury_function*)compile_output.data.p);//set the state's bytecode to the function we just compiled
  free(compile_output.data.p); //we no longer need the original struct pointer, but still need its data.
  while (mercury_stepstate(M)); //run the state's code
  mercury_destroystate(M); //destroy the state once finished. do not do this if you want to keep the data.
}
