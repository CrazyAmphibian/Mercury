FUNCTIONS

thread|nil new ( function function, [table enviroment=_ENV], variable ... )

creates a new thread with a given function, and immedietly begins execution. caution is advised when multithreading, as no safeguards are put in place to prevent data races.
optional second arg specifies an environment override to prevent the thread from modifying global data. can be supplied with nil to ignore it.
accepts any number of further arguments, which will be supplied to the thread function as parameters.
returns a thread object on successful thread start, or nil if the thread failed to start.
if no return value is specified, the thread will not be created.

notes on thread safety

privative datatypes can be safely read, but their values can potentially change mid-read
referenced types can be read with the same data race issues, but if a reference is removed, the variable may potentially free while still in use, leading to a crash.
accessing variables from structures (including the environment) has the same caveats as referenced type reading.
setting variables in structures should not be done, as the internal pointers will change, resulting in the program reading memory no longer in use, which can lead to data corruption or a crash.
C functions are completely safe to use, barring other type complications, as they are immutable, however some are not thread safe to execute.

it is recommended to not use global variables while in a thread, including standard library tables.
If you are unsure, it is best advised to set the environment parameter to an empty table, and pipe in everything you need in a dedicated single level table, or individual parameters

 return 20

bool isfinished (thread thread)

returns a bool if a thread has finished execution.

b=thread.isfinished(t)


bool isrunning (thread thread)

returns a bool if a thread is executing code.
will always returns the inverse result of isfinished.

b=thread.isrunning(t)


variable|nil fetch (thread thread)

returns the next variable from a finished thread.
if there are no more variables returned by the thread, nil will be given instead
Will halt execution of the main thread to wait for the thread to finish.

a=function(n)
return n*2,n+5
end

t=thread.new(a,{},10)

thread.fetch(t) //returns 20
thread.fetch(t) //returns 15
thread.fetch(t) //returns nil


void abort (thread thread)

kills a thread. This should only be used in dire circumstances where a thread is held up indefinitely, as resources will not properly be freed.

thread.abort(t)


int getcount (thread thread)

returns the next number of results that a thread has in the form of an integer, or 0, if the thread is still running.

while thread.getcount(t) do
 thread.fetch(t)
end


int await (thread thread)

halts the main thread until the supplied thread is finished.

thread.await(t)


void break (thread thread)

attempts to stop a running thread by forcing it to stop bytecode execution.
preferable to thread.abort, as it allows for variables to be properly freed.
does nothing on a thread that has finished executing.

thread.break(t)


bool checkerror (thread thread)

returns a boolean if a thread encountered an error.

thread.checkerror(t)
