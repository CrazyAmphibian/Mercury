2.4 making C++ function 2.5 refcounting

what is a reference, anyways?

all complex variables (variables that cannot be expressed as a single datapoint) are dynamically allocated, meaning that their use has to be tracked, so that they may be properly freed.
freeing too early means accessing memory that no longer belongs to the program, which may result in garbage data or a crash.
freeing too late means that resource use will accumulate in a memory leak scenario.

to circumvent this, mercury attaches reference counts to every variable that is dynamically allocated.
a variable starts with 0 references.
when a variable leaves a function, it should be checked for references, and if 0, freed. this is done with mercury_release_var, which handles the ref checking, as well as free logic.
this means that if you want to store a variable for later, you must add a reference, and remove it when the variable leaves storage. this is done with mercury_increment_variable_refrence_count and mercury_decrement_variable_refrence_count respectively.
when adding a reference, calling mercury_release_var is redundant, and can be skipped.
and when you can guarantee a type is a primitive, this can be skipped as well, since they are an unrefed type.

mercury's structures qualify under this, and require reference counting to values placed in them.
for arrays, mercury_setarray can be used, which will automatically manage the reference count of both the variable being supplied, as well as the variable already at the index. this means that once you set an array value, you can keep using it afterwards, and not worry about releasing the variable.

similarly, tables have an equivalent mercury_setkey function. values and keys are both managed by the function. the function will guarantee that the key supplied will be increased in reference (and lower the refcount of the existing key, potentially freeing it). this means that you can pass a value and key to this function, and keep using both variables afterwards, at least for the duration of your function, and assuming you are setting different keys. likewise with arrays, releasing variables passed into this isn't required.

getting values is a bit different. for arrays, mercury_getarray can be used. the returned variable does not need to be released, or have its refrence count changed so long as it remains in the array.

for tables, the same is true of the value, when you use mercury_getkey. however, the supplied key needs to be treated like a normal variable, as its references are unchanged, meaning calling mercury_release_var before function closure.
