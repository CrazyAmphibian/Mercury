Mercury is an interpreted dynamically-typed language, with a simple but robust syntax.

Why Mercury?

Though a high-level language, Mercury doesn't compromise programmer freedom for the sake of simplicity. Code is extremely flexible, while still maintaining atomicity for functions and variable to keep order where it matters.

Mercury is also easy to embed in other programs, thanks to its accessible C++ roots.

With features such as garbage collection and first class functions, Mercury is more than capable of standing up as a language on its own.

Design Philosophy

Mercury is designed around a core set of ideas

    Mercury should be...
  • Fast
    • Mercury should be fast, both in execution and in writing, without sacraficing other features.
  • Simple
    • Mercury should have a minimal syntax, with no overlap in functionality or ambiguous functionality
  • Flexible
    • Mercury should allow as many styles of programming as possible, without compromising the experience of non-users.
    • Mercury should have a diverse set of useful library functions that act to support, but not replace a programmer.
  • Compatible
    • Mercury should be able to run on as many machines as possible, and have minimal deviance in results on different hardware.
    • Mercury should not needlessly remove, change, or deprecate existing functionality
