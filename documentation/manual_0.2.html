Variable Types

Mercury has 11 distinct datatypes. All variable types in mercury are first class, meaning they can be freely stored or passed to functions.

  • nil
    • Represents nothing, undefined variables, and recoverable errors
    • Evaluates as false
    • Primitive value
  • int
    • Represents signed integer values
    • Evaluates as true is the value is not 0
    • Primitive value
  • float
    • Represents floating point numbers
    • Evaluates as true regardless of value
    • Primitive value
  • bool
    • Represents a boolean value.
    • Evaluates according to it's value
    • Primitive value
  • table
    • Represents an associative dictionary
    • Evaluates as true regardless of contents
    • Referenced value
  • string
    • Represents a series of characters, such as words.
    • Evaluates as true regardless of contents
    • Referenced value
  • c function
    • Represents a function written in C++ using mercury's backend API
    • Evaluates as true
    • Immutable value
  • array
    • Represents an array of values
    • Evaluates as true regardless of contents
    • Referenced value
  • function
    • Represents a function written in mercury
    • Evaluates as true regardless of contents
    • Referenced value
  • file
    • Represents a handle to a file on the system
    • Evaluates as true regardless of state
    • Referenced value
  • thread
    • Represents a handle to a thread object
    • Evaluates as true regardless of state
    • Referenced value

nil

nil is a special datatype, with some exceptions and special behavior.
This is because besides being a valid variable, it is also used for invalid data, too.

for example, functions, when provided with nil, are not guaranteed to treat the nil value as if it were provided. In some cases this is useful, as it means nil can act like a default argument in a function with multiple optional args.
in other cases, such as data traversal and iteration, nil is almost always ignored as a value, and will not be processed.

due to this, it is not recommended to use nil as a value for anything you want complex explicit behavior for.
regardless, nil is still first class, and is able to be used for indexes of tables, passing to functions, and variable assignment, and the language will remember its value.
nil can be created with its associated keyword.

a = nil

int and float

int and float, while 2 distinct types with slightly different semantics, are in many cases interchangeable as a grouped "number" type.

ints will be promoted to floats in cases where the 2 types mix, though in some cases, floats will be truncated into ints.

integers have multiple creation syntaxes

a = 1 //standard signed integer creation syntax
a = 0xF10C //unsigned hexadecimal creation syntax
a = 0b110010 //unsigned binary creation syntax

while floats have one syntax, which just involves a period and a number`

a = 1.0
a = 1. //this is also ok
a = .0 //and this, too

bool

though every type can be used in comparisons, booleans are the intended method, as their behavior is gaurenteed

booleans can be created with keywords, or with comparisons

a = true
a = false
a = b>c

table and array

tables store data in a key-value format, where each value is associated with, and retrieved by a key. each key associated with one value, and each value can only be associated with one key (though the value can be copied into other keys)

tables are created with curly brackets, and have 2 value modes, implicit and explicit. implicit values start at 0, and increment upwards.

a = {} //empty table
a = {"a",7,false}
a = {"id"=7,"here"=false}

explicit values can be defined with variables, too. variables are stored as their value, and not a reference to the variable, so if the variable is changed after setting, it will not return the initial value.

a = "test"
b = {a=true} // equal to "test"=true
b = {"a"=true} // not to be confused with this.

and indexing is done with brackets. periods can also be used to index tables, and treat the index like a string

a = {"var1"=true,"var2"=false}
print(a["var1"]) // true
print(a.var2) // false

tables are refrences, and share values between all copies

a = {"var"=5}
b=a
a.var2 = 6
print(b.var2) // 6

arrays are used in a very similar manner and with similar quirks to tables, except they are created using square brackets, and can only store integer indexes. arrays are much faster and memory efficient with consecutive data, and tables are faster and efficient with sparse or mixed data.

a = [1,2,3]
b = [0=1,1=2,2=3] //same data, explicit indexes

string

Strings represent any number of any kind of characters, including NULL.

strings are created with double quote marks, and will cross any number of characters until a closing quote is found

a = "hello"
b = "hello

there" //string includes the newlines

strings are escaped with backslash (\), and have similar rules to C's escapes

sequence result
\\ \
\" "
\' '
\t tab
\n newline
\r carriage return
\? ?
\a bell
\b backspace
\e ASCII escape (0x1B)
\f formfeed
\v vertical tab
\x00 hex character input
\123 decimal character input

strings can be indexed (but not assigned to) using the index syntax, given an integer. doing so returns a 1 character string of the character at that index (starting at 0). if an out of bounds integer is provided, an empty string will be given instead.

a="test"
print(a[0],a[3]) // t t

functions and C functions

functions of any type can be called the same way, using parenthesis, and delimit args with commas

print(6) //c function
my_function(12,6) //mercury function
