default visibility behavior

by default, when a variable used, the Mercury runtime will first search outwards for a variable with the same name (a variable counts as defined even if it is nil).
if an existing variable is found, that is what will be assigned to or retrieved from.
if no variable exists, one will be created in the innermost code body.
this process is done every time a variable is accessed.

stuff=function()
a=10
end

//scenario 1: a was defined before the function call
a=5
stuff() //looks for a, and finds a exists, and sets it to 10 print(a) //10

//scenario 2: a was not defined before the function call
stuff() //looks for a, and does not find it, and so creates a variable.
print(a) // the variable was created in the function body's state, and so is not visible here.

local keyword

the local keyword is placed before a named variable, on either the get or set side. It tells the compiler that it is to search only inside the innermost state for the variable.

stuff=function()
local a=10
end

a=5
stuff() // a is marked as local, and so it is created inside the function's state, and never sees the outside variable of the same name.
print(a) //5

stuff=function()
 local a=a
 a+=20
 print(a)
end

a=5
stuff() //prints 25, because it takes a=5 from here and adds 20 to it.
print(a) //still 5, because the function copied the variable a into a local variable, whose modifications do not propagate back to the host state.

global keyword

the global keyword is used in the same manner as local, but instead makes the variable go to the topmost (global) state.

stuff=function()
global a=10
end

stuff() // a is marked as global, so it checks the topmost state, and sets the value.
print(a) //10

the two keywords can be used together to create some strange effects

stuff=function()
 local a=a
 a+=20 //default access looks for locals before globals
 print(a, global a)
end

global a=5
stuff() //prints 25 5, because the local version is created then added by 20, while the global version remains unchanged
